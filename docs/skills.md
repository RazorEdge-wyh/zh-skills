# zh-skills 技能详解

每个技能都是一个标准的 Claude Code Skill（`.claude/skills/<name>/SKILL.md`）。
`description` 里的关键词决定它什么时候被自动激活，正文是该技能的执行规范。

安装后，文件就在你的项目里——**改它，就是定制你们团队的规范**。

---

## 🔍 code-review-zh — 中文工程规范代码审查

**触发**：审查 / review / 检查代码

- 按 6 个维度审查：命名、注释、可读性、错误处理、边界安全、性能。
- 每个问题输出：`文件:行号` + 严重程度（🔴🟡🟢）+ 为什么 + 怎么改。
- 专检中文项目的"特产"：拼音命名（`jine`/`shijian`）、翻译腔注释、神秘缩写。
- 审查输出遵循"结论先行、证据充分、语气中性"。

**适合**：PR review、接手旧代码、合入前的规范门禁。

---

## 📝 write-doc-zh — 地道中文技术写作

**触发**：写 / 改文档或注释

- 内置 README 结构模板（定位 → 特性 → 快速开始 → 使用 → 配置 → 工作原理）。
- 翻译腔对照表：`对数据进行一个排序的操作` → `给数据排序`；`通过使用 X` → `用 X`。
- 排版规范：中英文之间加空格、数字用阿拉伯数字、命令语气。
- 接口文档规范：请求方法 + 参数表 + 响应示例 + 错误码表。
- 自带交接清单，写完了逐项自查。

**适合**：写 README、接口文档、把英文文档翻译成地道中文。

---

## 🪵 commit-zh — 中文 Conventional Commits

**触发**：生成 git commit message

- 标准格式：`<type>(<scope>): <中文描述>`。
- 11 种 type 速查表（feat/fix/docs/style/refactor/perf/test/build/ci/chore/revert）。
- 描述规范：动词开头、说"改了效果"不说"改了代码"、一个 commit 一个意图。
- 好/坏示例对照，团队可直接截图贴到群里。
- 配套建议：commitlint 配置、自动生成 CHANGELOG。

**适合**：统一团队提交风格，生成规范 changelog。

---

## 🧹 refactor-zh — 安全重构

**触发**：重构 / 清理 / 优化代码

- 铁律：行为不变、小步提交、可随时回滚、先有测试再动手。
- 动作清单按性价比排序：命名规范化 → 注释优化 → 函数拆分 → 去重复 → 死代码清理 → 结构整理。
- 每次重构一个动作一个 commit，message 标注"纯重构：无行为变化"。
- 涉及公共 API 变更必须高亮提醒。

**适合**：把英文思维写的中文项目改造成规范、可维护的状态。

---

## 🏥 health-check-zh — 中文工程健康体检

**触发**：体检 / 健康检查 / 评估项目

- 100 分制，四维评分：文档健康（30）、AI 协作（25）、命名健康（25）、代码卫生（20）。
- 输出：总分 + 档位（优秀/良好/一般/危险）+ 做得好 + 待修复（按收益排序）。
- 每个待修复项：位置 + 问题 + 改成什么，一句话能执行。

> CLI 里的 `zh-skills doctor` 是它的静态启发式版本（不调用模型，秒出报告）；
> 让 Claude Code 在会话里做体检则用这个技能（更智能，能理解上下文）。

---

## 自定义成你们的规范

技能文件就在 `.claude/skills/`，直接改即可：

```text
your-project/.claude/skills/commit-zh/SKILL.md   # 改这个文件，就是改你们团队的 commit 规范
```

改完 Claude Code 下次启动自动生效。想团队统一？把这个文件提交到仓库，全员同步。

## 想新增一个技能？

在 `.claude/skills/<name>/SKILL.md` 写一个带 frontmatter 的 Markdown 即可：

```markdown
---
name: my-rule-zh
description: 在 <触发场景> 时使用。一句话说明它管什么。
---

# 规范正文（规则 + 示例 + 输出格式）
```

欢迎把好用的规范贡献回 zh-skills（见仓库 Issue/PR）。
